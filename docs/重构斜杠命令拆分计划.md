# 重构：斜杠命令从 index.ts 拆分到 commands 目录

## 目标

将 `index.ts` 中的两个斜杠命令（`/chrome-start`、`/chrome-stop`）拆分到 `commands/` 目录，一个命令一个文件。
共享状态提取到 `core/shared-state.ts`，使命令文件只需接收 `pi` 一个参数。

## 当前结构

```
index.ts              ← 所有东西都在这里（命令、事件处理、共享状态、工具注册）
core/
  browser.ts
  console-buffer.ts
  connection-state.ts
  selector-utils.ts
  types.ts
tools/                ← 一个工具一个文件（已拆好）
  find-elements.ts
  trace-css.ts
  ...
```

## 目标结构

```
index.ts              ← 组装：注册命令、注册事件、消息渲染器、establishConnection
commands/
  chrome-start.ts     ← /chrome-start 命令
  chrome-stop.ts      ← /chrome-stop 命令
core/
  shared-state.ts     ← 共享状态（新增）
  types.ts            ← 纯类型定义（不变）
  ...（其余不变）
tools/                ← 不变
  ...
```

## 步骤

### 1. 新建 `core/shared-state.ts`

提取以下共享状态为模块级变量：

```ts
import { ConsoleBuffer } from './console-buffer';

let toolNames: string[] = [];
const consoleBuffer = new ConsoleBuffer();

// getter / setter
export function getToolNames(): string[] { return toolNames; }
export function setToolNames(names: string[]): void { toolNames = names; }
export function getConsoleBuffer(): ConsoleBuffer { return consoleBuffer; }
```

用 getter/setter 而不是直接暴露变量，封装访问方式。

> **注意**：`core/types.ts` 不与 shared-state 合并。原因是消费者不同——types.ts 是纯类型定义，被 `tools/` 的工具文件 import；shared-state.ts 是运行时可变状态，被命令文件和事件处理 import。合并会让工具文件间接拉进 ConsoleBuffer 实例化。

> **注意**：`isReconnecting` 不提取到 shared-state，保留为 `index.ts` 的局部变量。它只在 `/chrome-start` 的并发保护（检查）和 `session_start` 事件处理（设置）中使用，都在 index.ts 内部，不需要跨文件共享。

### 2. 新建 `commands/chrome-start.ts`

- 导出 `registerChromeStart(pi: ExtensionAPI, establishConnection: (ctx: ExtensionContext) => Promise<void>)`
  - `establishConnection` 定义在 index.ts 中，作为回调传入。它内部通过闭包访问 `pi`（不是通过参数），命令文件只需把它传递给 handler 即可
- handler 逻辑从 `index.ts` 原样搬入
- 共享状态（`toolNames`）通过 `core/shared-state` 的 getter/setter 访问

### 3. 新建 `commands/chrome-stop.ts`

- 导出 `registerChromeStop(pi: ExtensionAPI)`
- 逻辑简单，从 index.ts 原样搬入
- 共享状态通过 `core/shared-state` 的 getter/setter 访问

### 4. 精简 `index.ts`

重构后 `index.ts` 只负责：

1. 定义 `establishConnection`（含 `registerTools`、断线回调注册）—— **必须保持为 index.ts 的 inner function**，因为它通过闭包访问 `pi`（来自外层 `export default` 函数参数），且调用 `registerTools`。调用处需更新：`toolNames = registerTools(pi, consoleBuffer)` → `setToolNames(registerTools(pi, getConsoleBuffer()))`
2. 注册自定义消息渲染器（`chrome-disconnected`、`chrome-reconnected`）—— 保留在 index.ts，不随命令文件移动
3. 注册命令：`registerChromeStart(pi, establishConnection)`、`registerChromeStop(pi)`
4. 注册事件：`session_start`（自动重连）、`session_shutdown`（清理）—— 保留在 index.ts，因为它们调用 `establishConnection`
5. 维护 `isReconnecting` 局部变量（仅供 `session_start` 和传给 `registerChromeStart` 的 handler 使用）

预计从 ~200 行降到 ~100 行。

#### `index.ts` import 变更

```
删除：  import { ConsoleBuffer } from './core/console-buffer';
新增：  import { getToolNames, setToolNames, getConsoleBuffer } from './core/shared-state';
新增：  import { registerChromeStart } from './commands/chrome-start';
新增：  import { registerChromeStop } from './commands/chrome-stop';
保留：  其余 import 不变（browser, connection-state, tools/*, types, pi-coding-agent, pi-tui）
```

#### `registerTools` 函数

保留为 index.ts 的私有函数（不 export），仅被 `establishConnection` 内部调用。不是命令，不搬入 commands/。

## 关键约束

### `onDisconnected` 回调的闭包处理

`onDisconnected` 回调在 `establishConnection` 内部注册，引用了三个外部依赖：
- `toolNames` → 改为 `getToolNames()` / `setToolNames([])`
- `pi` → 通过闭包访问外层函数参数（`export default` 的 `pi`），不需要额外传参
- `consoleBuffer` → 改为 `getConsoleBuffer()`

回调留在 `establishConnection` 内部，只把直接变量引用改为 shared-state getter。回调内 `toolNames = []` 改为 `setToolNames([])`。

### `session_shutdown` 的清理

```ts
pi.on('session_shutdown', async (event) => {
  if (browser.isConnected()) {
    setToolNames([]);
    getConsoleBuffer().stopListening();
    await browser.disconnectChrome();
  }
  if (event.reason === 'quit') {
    clearConnectionState();
  }
});
```

`disconnectChrome()` 会触发 puppeteer 的 `disconnected` 事件，但 `browser.ts` 的处理逻辑会检查 `isDisconnecting` 标志——主动断开时回调被跳过，不会触发 `onDisconnected`。所以这里的清理顺序不涉及断线回调约束，按自然顺序清理即可（清空状态 → 停监听 → 断开连接）。

真正的 `onDisconnected` 回调只在**非主动断开**时触发（如其他进程 kill Chrome），此时 `isDisconnecting === false`，回调会执行通知逻辑。

### 错误处理模式

命令文件需保持一致的错误处理模式：
- 参数解析错误 → `ctx.ui.notify('❌ ...', 'error')` + return
- 连接失败 → 清理 shared-state + 通知
- 自动重连失败 → 静默清理 + 通知

## 不变的部分

- `tools/` 目录不动
- `core/browser.ts`、`core/connection-state.ts` 等不动
- `registerTools` 函数保留在 index.ts（私有函数，不 export）
- `core/types.ts` 不动（不与 shared-state.ts 合并）
- `isReconnecting` 保留为 index.ts 局部变量（不需要跨文件共享）
